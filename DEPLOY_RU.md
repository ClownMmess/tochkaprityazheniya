# Как разместить «Точку притяжения» и сдать проект

Сборка 1.3.2. Инструкция для Windows и нового сервера Ubuntu. Проверка цен: 30.09.2026.

## 1. Что потребуется от команды

1. Доступ к настройкам выданного бота MAX, его имя пользователя и действующий токен. Токен, уже опубликованный в переписке, перед публичным запуском лучше заменить.
2. Аккаунт и оплата облачного сервера. Покупать физическое оборудование не нужно.
3. Домен или поддомен, которым вы можете управлять. Если есть университетский поддомен, новый домен покупать не требуется.
4. Два аккаунта MAX для проверки совместной подборки в мобильном приложении и веб-версии.
5. Настоящий состав команды и распределение ролей для презентации.
6. Доступ к форме сдачи конкурса и точное время дедлайна. В PDF трека адрес формы и дедлайн онлайн-этапа отсутствуют.

## 2. Недорогой сервер

Самый дешёвый из найденных и подтверждённых на официальной странице вариантов с 4 ГБ памяти — FirstByte, **MSK-highmem-KVM-SSD-2**: 2 vCPU, 4 ГБ RAM, 30 ГБ SSD. На странице указана акционная цена **499 ₽/месяц**, рядом обычная 579 ₽. Это цена предложения на дату проверки, не гарантия будущего счёта.

Ссылка: https://firstbyte.ru/vps-vds/kvm-ssd/ — раздел «Тарифные планы на VDS с увеличенным количеством оперативной памяти».

Выберите Москву, Ubuntu 24.04, срок 1 месяц. Нужен один публичный IPv4. Дополнительную панель ispmanager и платный SSL для этой сборки покупать не требуется. До оплаты проверьте итог корзины, включение IPv4, наличие тарифа, дату продления и условия скидки: состав заказа доступен только после входа. Если итоговая цена отличается, ориентируйтесь на счёт провайдера.

Более дешёвый MSK-highmem-KVM-SSD-1 стоит 349 ₽/месяц, но имеет 2 ГБ памяти и 25 ГБ диска. Для параллельной сборки и базы запас мал; под конкурс рекомендованы 4 ГБ. Разница по опубликованной акции — 150 ₽/месяц.

Сравнение подходящих вариантов:

| Провайдер | Память / диск | Опубликованная стоимость |
|---|---|---|
| FirstByte highmem-2 | 4 ГБ / 30 ГБ | 499 ₽/мес по акции, рядом 579 ₽ обычная |
| Beget | 4 ГБ / 40 ГБ | 33 ₽/день + 5 ₽/день IPv4, около 1 140 ₽ за 30 дней |
| VDSina Standard | 4 ГБ / 100 ГБ | 40 ₽/день, 1 200 ₽ за 30 дней |

Источники: https://beget.com/ru/vps и https://vdsina.ru/pricing/standard. Сравнение ограничено проверенными предложениями, оно не доказывает минимальную цену во всём интернете. Скорость и доступность конкретной ВМ до аренды не тестировались.

Cloud.ru Free Tier не включён в рекомендацию: по актуальной документации новые бесплатные ВМ недоступны аккаунтам, зарегистрированным после 30.06.2026. Старый аккаунт может иметь право на Free Tier, но публичный IP оплачивается отдельно, гарантированная доля CPU ограничена. Источник: https://cloud.ru/docs/virtual-machines/ug/topics/overview__free-tier.

На старт закладывайте цену сервера плюс домен по счёту регистратора. Внешняя платная LLM не нужна. Суммы в инвесторской модели включают организацию пилота и привлечение пользователей; полноценная зарплата основателей в них не заложена, их не нужно оплачивать для технического запуска.

## 3. Домен и сетевые настройки

Зарегистрируйте свободный домен либо используйте имеющийся. Для поддомена afisha.example.ru создайте DNS-запись типа A: имя `afisha`, значение — публичный IPv4 сервера. `example.ru` здесь пример, не готовый адрес приложения. Не добавляйте AAAA, если IPv6 сервера не настроен.

В панели сетевого экрана сервера разрешите входящие TCP 80 и 443 для сайта и TCP 22 для SSH. Если на самой Ubuntu включён ufw, разрешите эти порты и там. Не публикуйте 5432 и 8000.

В PowerShell можно проверить DNS:

```powershell
nslookup afisha.ВАШ-ДОМЕН.ru
```

Ответ должен содержать IP сервера. Распространение DNS занимает время. Caddy получит бесплатный HTTPS-сертификат автоматически после запуска, если DNS и доступ к 80/443 настроены.

## 4. Передача файлов с Windows

1. Распакуйте MAX_app_v1_3_2_submission.zip. Внутри папка `max-afisha`.
2. Установите WinSCP с https://winscp.net/eng/download.php и создайте соединение SFTP.
3. Укажите IP сервера, порт 22, логин и пароль/ключ, полученные у провайдера.
4. Передайте папку проекта в `/opt`, чтобы получился путь `/opt/max-afisha/compose.yaml`. При ограниченном пользователе можно загрузить в домашнюю папку и переместить через sudo.
5. Не переносите `.env` со своего компьютера при первом размещении. Новая серверная база начинает с исходного каталога, без локальных профилей и голосов.

## 5. Подключение и установка Docker

На компьютере откройте PowerShell:

```powershell
ssh root@IP_СЕРВЕРА
```

Вместо root используйте логин от провайдера, если он другой. Сверьте отпечаток SSH при первом подключении с панелью сервера. Следующие команды вводятся уже на сервере:

```sh
cd /opt/max-afisha
sudo bash scripts/install-docker-ubuntu.sh
```

Скрипт использует официальный apt-репозиторий Docker. Если Docker и Compose уже установлены, он завершится без переустановки. Источник команд: https://docs.docker.com/engine/install/ubuntu/.

## 6. Настройка без ручного копирования секретов

```sh
sudo python3 scripts/configure-production.py
```

Введите по запросу:

- домен без https:// и без завершающего /;
- имя пользователя бота без @;
- токен бота. При вводе символы не отображаются, это нормально.

Скрипт создаёт `.env`, генерирует секреты и записывает рабочие настройки. Пароль существующей базы не меняется. По умолчанию отключена тяжёлая локальная LLM и включено обновление открытого API KudaGo раз в 6 часов. Подготовленные записи других источников остаются в каталоге с исходной датой получения.

## 7. Сборка и запуск

Для замера конкурсного требования выполните на сервере:

```sh
sudo python3 scripts/measure-build.py
```

Скрипт сначала скачает базовые образы, потом запустит сборку приложения без кеша. В результате должны быть `build_exit_code: 0` и `within_300_seconds: true`. Если сборка дольше пяти минут, норматив не пройден: проверьте CPU, скорость загрузки пакетов и нагрузку, при необходимости временно увеличьте ресурсы. Не выдавайте повторную сборку из кеша за холодную проверку.

Затем запустите сервисы:

```sh
sudo docker compose -f compose.yaml -f compose.production.yaml up --build -d --force-recreate --wait --wait-timeout 900
```

Загрузка каталога происходит при старте API после сборки. При первом запуске дождитесь её окончания.

Проверка:

```sh
sudo docker compose -f compose.yaml -f compose.production.yaml ps
```

API и база должны быть healthy, остальные сервисы — запущены. Откройте `https://ВАШ-ДОМЕН/health`, затем `/api/v1/runtime`. Ожидаются status=ok, catalog_version=1.3.2, demo_mode=false. В браузере вне MAX просмотр каталога доступен, а профиль и голосование требуют входа через MAX.

## 8. Подключение к MAX

На https://business.max.ru/ откройте Чат-боты, выберите выданного команде бота, затем ⋮ → Настройки. Укажите HTTPS-адрес и кнопку «Открыть». Если конкурс использует отдельный кабинет, укажите ссылку там по инструкции организаторов.

Официальная инструкция: https://dev.max.ru/help/miniapps. Если есть токен, но нет доступа к настройкам бота, попросите организаторов подключить URL или предоставить доступ. ZIP в это поле не загружается.

Название: «Точка притяжения». Логотип: `frontend/public/logo.png`.

На сервере:

```sh
sudo docker compose exec api python bot_manage.py inspect
sudo docker compose exec api python bot_manage.py subscribe
sudo docker compose exec api python bot_manage.py subscriptions
```

Первая команда должна показать вашего бота. Подписка должна содержать `https://ВАШ-ДОМЕН/api/v1/max/webhook`. Команды не выводят токен. При ошибке сначала проверьте данные бота, сертификат и ответ API MAX.

## 9. Проверка двумя участниками

Откройте бота, начните диалог и нажмите «Открыть». Заполните интересы. Найдите концерты, добавьте 2–5 вариантов, создайте подборку, поделитесь ею со вторым участником. Он должен видеть скрытые результаты до своего голоса, выбирать несколько событий и отменять голос повторным нажатием.

Проверьте этот сценарий на телефоне и в web.max.ru. Затем включите отслеживание будущего сеанса: личное подтверждение должно прийти от бота. Начатый диалог с ботом обязателен для проверки его сообщений. Модальное окно «чат не создан» при отсутствии чата — ожидаемое поведение MVP.

## 10. Заполнение комплекта сдачи

До дедлайна, в папке исходников:

```sh
python3 scripts/prepare-submission.py
```

На Windows используйте `py` вместо `python3`. Скрипт запросит публичный HTTPS-адрес, имя бота, ссылку/версию кода и состав команды. Он заполнит OpenAPI, DATA-API и `submission-info.json`. Скопируйте эти сведения на первый слайд PPTX и на слайд команды. Экспортируйте презентацию в PDF в PowerPoint: Файл → Экспорт → Создать PDF/XPS.

На первом служебном слайде нужно заменить поля «заполнить после размещения»: ссылка MAX, домен API, код/commit и необходимые проверяющим доступы. Рабочие токены, которые регламент просит на служебном слайде, передавайте только закрытым каналом организаторов. Публичная и инвесторская копии презентации остаются без секретов. Паролей собственного сервиса нет, вход выполняется через MAX. Тестовый Bearer-токен пользователя действует один час и не подходит как вечный доступ.

Регламент разрешает Git-репозиторий с commit hash или архив с контрольной суммой. Однако на слайде перечисляет репозиторий и commit. Для однозначной сдачи предпочтителен репозиторий; для архива уточните замену полей у организаторов. Не загружайте `.env`, `backup.sql`, node_modules, локальную базу и личные данные. Если репозиторий закрытый, предоставьте жюри доступ через предусмотренный конкурсом канал.

После последних изменений заархивируйте исходники и получите SHA-256:

```powershell
Get-FileHash ".\MAX_app_v1_3_2_submission.zip" -Algorithm SHA256
```

Контрольная сумма выданного здесь архива изменится после заполнения ваших адресов: используйте сумму именно отправляемой версии. После дедлайна не меняйте переданную версию кода и презентацию до разрешения финалистам.

## 11. Что отправить

- Ссылку на работающее мини-приложение в MAX, доступное весь период проверки.
- PDF-презентацию с заполненным служебным первым слайдом и составом команды.
- Ссылку на код и commit hash либо окончательный ZIP и SHA-256.
- README, Dockerfile/Compose, .dockerignore, .env.example и зафиксированные зависимости (всё уже в исходниках).
- HTTPS-адрес API, `openapi.json`, `DATA-API.yaml`, `review-data.json` и необходимые доступы для проверки.

Форма сдачи и время дедлайна в PDF трека не указаны. Уточните их в кабинете/чате конкурса. Приложение должно оставаться онлайн: по регламенту один исходный архив не заменяет работающий MAX-сценарий.

## 12. Если что-то не запускается

Если API unhealthy:

```sh
sudo docker compose -f compose.yaml -f compose.production.yaml logs --tail=100 api db
```

Если нет HTTPS:

```sh
sudo docker compose -f compose.yaml -f compose.production.yaml logs --tail=100 https
```

Проверьте DNS, входящие 80/443, отсутствие другой программы на этих портах. Если бот отвечает ошибкой авторизации, проверьте совпадение токена с ботом, к которому подключён URL. Если не приходят сообщения, начните диалог с ботом и проверьте subscriptions и logs worker.

Перед обновлением можно сохранить базу:

```sh
sudo docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

Остановка всех production-сервисов:

```sh
sudo docker compose -f compose.yaml -f compose.production.yaml stop
```

Повторный запуск с сохранением данных:

```sh
sudo docker compose -f compose.yaml -f compose.production.yaml up -d
```

Не используйте `down -v`: он удаляет том базы. Сервер продолжает тарифицироваться и после остановки контейнеров. После размещения ваш компьютер можно выключать.
