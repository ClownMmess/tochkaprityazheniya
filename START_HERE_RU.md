# Точка притяжения · 1.3.1

Эта версия сделана из прикреплённого MAX_app_v1_3.zip. Сохранены интерфейс 1.3, зелёная палитра, 11 направлений / 57 тем интересов, подсказки поиска, окно фильтров, лента и подборки из 2–5 событий. Это веб-приложение для запуска внутри MAX; отдельное мобильное приложение устанавливать не нужно.

## Обновить существующую версию на Windows

1. Сохраните резервную копию вашей папки проекта и файла `.env`. Старая база хранится в Docker, а не в ZIP.
2. Откройте PowerShell в прежней папке `max-afisha` и выполните `docker compose stop`. Эта команда сохраняет базу.
3. Распакуйте папку `max-afisha` из нового архива **в ту же папку проекта**, с заменой файлов. Не создавайте вложенную папку `max-afisha/max-afisha`. Сохраните прежний `.env` и пароль PostgreSQL. В архиве личного `.env` нет.
4. Запустите `start-demo.bat`. После первого обновления загрузка каталога может занять несколько минут.
5. Откройте <http://localhost:8080>. Если вкладка уже была открыта, нажмите Ctrl+F5. Внизу страницы должна быть версия **1.3.1**.

Не используйте `docker compose down -v`: эта команда удаляет базу с профилями и голосами. Сохраняйте прежнее имя папки и Compose-проекта: так приложение подключится к прежнему тому базы. Миграция автоматически добавляет возможность нескольких голосов и сохраняет существующий голос.

При копировании поверх старой папки лишние старые файлы не удаляются автоматически. Можно удалить оставшиеся папки `backend/tests`, `backend/tests_techlead`, `frontend/scripts`, старую `docs` и `MOBILE_PREVIEW.html`: в этой версии они не используются.

## Первый запуск

Нужен работающий Docker Desktop с Linux-контейнерами. Распакуйте архив и дважды нажмите `start-demo.bat`. Скрипт создаст `.env` с локальными секретами, соберёт приложение, создаст базу и откроет браузер. Для macOS/Linux: `sh start-demo.sh` из папки проекта; нужны Docker Compose и Python 3.

Локальный режим позволяет переключаться между Павлом и Аней в верхней панели, чтобы посмотреть голосование с двух сторон. События взяты из источников; сообщения в MAX в этом режиме не отправляются. В рабочем режиме MAX этой панели нет.

Если запуск остановился:

```powershell
docker compose ps
docker compose logs --tail=100 api catalog worker frontend
```

Сообщение `api is unhealthy` само по себе не показывает причину: она находится в журнале `api`. Не удаляйте базу для устранения ошибки. При занятом порте 8080 освободите его перед запуском.

## Как пользоваться

- В «Интересах» выберите город, возраст и направления. Карточка открывает темы; выбранные варианты выделяются цветом, без галочек. «Всё направление» выбирает его целиком.
- Напишите, например: «Нас 5 человек, хотим на концерт в Краснодаре», «Бесплатно» или «Стендап до 1000». Нажмите «Найти». Кнопки идей также подставляют запрос в строку.
- Подсказки появляются под строкой, а разобранные условия — в окне «Фильтры». Можно исправить их и нажать «Показать события». Ручной бюджет не перезаписывается запоздавшей подсказкой.
- Листайте ленту вниз: следующие страницы подгружаются автоматически. Кнопка «К поиску» возвращает наверх.
- «В подборку» добавляет событие, «В подборке» убирает его. Выберите 2–5 разных событий и нажмите «Создать выбор». Поделитесь ссылкой.
- В подборке сначала видны только кнопки «Голосовать». После первого голоса на всех карточках появляются количества участников. Можно голосовать за несколько событий; повторное нажатие на выбранную карточку отменяет голос. Если отменить все свои голоса, результаты снова скрываются.
- Число с `%` означает совпадение с вашими интересами. Наведите указатель на `?` или нажмите его на телефоне, чтобы увидеть расчёт. Без интересов отображается `—`. Это соответствие темам, а не прогноз того, насколько вам понравится событие.
- В подробностях доступны афиша, сеансы, ссылка на источник, отслеживание и «Найти чат события». Если чата нет, появится отдельное окно. Бот не модерирует чаты.

## Каталог, цены и поиск

Сохранены все загрузчики источников из 1.3 и добавлен Nethouse. При проверке этой сборки каталог содержал 7 211 записей для Москвы, 575 для Краснодара и дополнительные записи ближайших городов. Это записи источников: одно мероприятие может продаваться на нескольких площадках. В Краснодаре доступны 7 подтверждённых бесплатных вариантов, в Москве — 129. Числа меняются при обновлении; они не означают, что собраны вообще все городские мероприятия.

Сервис `catalog` обновляет источники при запуске и каждые 6 часов. Горизонт — до 6 месяцев, насколько расписания опубликованы площадками. Timepad используется только при наличии `TIMEPAD_API_TOKEN`; без ключа он не выдаётся за подключённый источник. Отдельные сайты могут быть недоступны или изменить разметку: такая загрузка отражается в журнале, последний каталог не обнуляется.

Бесплатные постоянные программы KudaGo больше не отбрасываются из-за служебных дат. Они помечены как места/программы без отдельного сеанса; часы посещения нужно уточнять у источника. Неизвестная цена не считается бесплатной. Диапазон 1200–4500 не проходит бюджет до 1000. Бюджет в основном поиске применяется к начальной цене билета; наличие конкретных дешёвых билетов проверяется у продавца. Цена на всю компанию делится на количество участников.

Если точного совпадения нет, ниже показываются реальные альтернативы. Возле них прямо указано, что изменено — категория, дата или бюджет. Они не смешиваются с точной выдачей.

Поиск естественным языком работает без внешнего ключа. Опциональная локальная модель из исходной сборки сохранена: `start-ai.bat` скачает Qwen 2.5 7B через Ollama (несколько гигабайт, достаточно памяти обязательно). Если модель не отвечает, приложение использует разбор запроса по правилам. Модель не сочиняет мероприятия. Запуск самой модели в этой среде не проверялся.

## Разместить приложение и подключить MAX

В MAX загружается **HTTPS-адрес работающего приложения**, а не сам ZIP. Нужны сервер с Docker Compose, домен, направленный на этот сервер, и доступ к настройкам вашего бота MAX. Архив подготовлен к размещению, но сервер и адрес за вас не зарегистрированы.

1. Передайте папку `max-afisha` на сервер, например через SFTP, и войдите по SSH. Сохраните `.env` только на сервере. При новом размещении выполните `python3 scripts/init_env.py`.
2. В `.env` оставьте созданные пароль базы и `SESSION_SECRET`; заполните:

```dotenv
APP_ENV=production
DEMO_MODE=false
APP_DOMAIN=afisha.your-domain.ru
PUBLIC_APP_URL=https://afisha.your-domain.ru
MAX_BOT_TOKEN=ваш_токен_бота
MAX_BOT_NAME=имя_бота_без_символа_@
MAX_WEBHOOK_SECRET=случайный_секрет_минимум_32_символа
CATALOG_REFRESH_ENABLED=true
CATALOG_REFRESH_SECONDS=21600
LLM_ENABLED=false
```

`init_env.py` уже создаёт случайный секрет webhook: можно оставить его. Переданный в переписке токен не включён в архив и клиентский JavaScript; внесите его в `MAX_BOT_TOKEN` самостоятельно. Не отправляйте `.env` вместе с исходниками на конкурс.

3. Домен должен разрешаться в IP сервера. Откройте входящие порты 80 и 443. Запустите:

```sh
docker compose -f compose.yaml -f compose.production.yaml up --build -d --force-recreate --wait --wait-timeout 900
```

Caddy настроен как HTTPS-прокси к приложению. Если получение сертификата ещё идёт, подождите и проверьте журнал:

```sh
docker compose -f compose.yaml -f compose.production.yaml logs --tail=80 https
```

Не подключайте `compose.demo.yaml` на рабочем сервере. Если прежде здесь работал demo-режим, указанная команда пересоздаст контейнеры с рабочими настройками и сохранит том базы.

4. Откройте ваш HTTPS-адрес в браузере. Проверьте `/health` и `/api/v1/runtime`: версия `1.3.1`, `demo_mode: false`. Профиль и голосование требуют входа из MAX.
5. В настройках бота на платформе MAX укажите этот HTTPS-адрес как URL мини-приложения и включите кнопку открытия. Название — «Точка притяжения». Логотип находится в `frontend/public/logo.svg` и `frontend/public/logo.png`. Для конкурсного кабинета используйте аналогичное поле URL, если организаторы выдали отдельный кабинет.
6. Проверьте токен и подключите получение событий бота:

```sh
docker compose exec api python bot_manage.py inspect
docker compose exec api python bot_manage.py subscribe
docker compose exec api python bot_manage.py subscriptions
```

`inspect` читает информацию о боте. `subscribe` регистрирует webhook `/api/v1/max/webhook`. Подписка нужна для начала диалога и работы личного бота, а не для модерации групп. Ошибка MAX в этих командах не означает, что токен проверен: сначала исправьте её по статусу ответа.

7. Откройте бота в MAX и начните диалог. Откройте мини-приложение его кнопкой. Заполните профиль, создайте подборку, поделитесь ей со вторым участником и проверьте несколько голосов и отмену. Включите отслеживание одного сеанса и проверьте личное подтверждение бота.

Авторизация проверяет подпись стартовых данных на сервере. Токен не передаётся в браузер. Приложение не создаёт чаты автоматически. Чтобы привязать уже существующий чат к событию, администратор выполняет:

```sh
docker compose exec api python -m app.cli register-chat --event-id UUID_СОБЫТИЯ --chat-id ID_ЧАТА --invite-link https://max.ru/ВАША_ССЫЛКА
```

UUID события доступен в ответе API подробностей (`id`, не `occurrence_id`). Администратор сам создаёт чат и задаёт действительную ссылку приглашения.

## Состав и передача проекта

`frontend` — интерфейс React; `backend` — FastAPI, поиск, MAX, миграции и загрузчики; `seed` — исходные снимки реальных источников и дополнение; `compose*.yaml`, `Dockerfile`, `Caddyfile`, `scripts` — запуск и размещение. Каталог обновляется сервисом `catalog`, личные уведомления обрабатывает `worker`.

Для передачи исходников достаточно этого ZIP. Удалены тестовые файлы и тестовые зависимости, старые отчёты, промты команды, галереи проверок, модератор и ненужные экрану функции календаря/жалоб. Миграции сохранены, включая старую схему: они нужны для обновления существующей базы. Рабочий поиск и режим локального просмотра сохранены.

Проверены сборка интерфейса, API поиска и фильтров, несколько голосов и их отмена, сокрытие результатов, миграция старых данных, интерфейс в браузере и сенсорный экран 390 px. Docker Desktop/PowerShell и реальный сеанс внутри MAX здесь не запускались; эти пункты надо пройти на ваших устройствах после размещения. База и личный токен в ZIP отсутствуют.

Документация: [подключение мини-приложения](https://dev.max.ru/help/miniapps), [MAX Bridge](https://dev.max.ru/docs/webapps/bridge), [проверка подписи](https://dev.max.ru/docs/webapps/validation), [HTTPS-прокси Caddy](https://caddyserver.com/docs/quick-starts/reverse-proxy).
