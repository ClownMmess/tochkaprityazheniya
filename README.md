# Точка притяжения

Версия 1.3.2. Студенческий MVP для трека «Досуг и развлечения» MAX.

## Назначение и основной сценарий

Приложение помогает компании друзей выбрать досуг в своём городе с учётом интересов и бюджета. Пользователь открывает бота MAX и мини-приложение, заполняет город и интересы, ищет событие, добавляет 2–5 вариантов в подборку и отправляет её друзьям. Участники голосуют за несколько вариантов и могут отменять голоса. До первого собственного голоса результаты скрыты на сервере. После отмены всех голосов результаты снова скрываются.

Билеты покупаются на сайте первоисточника. Само приложение билеты не продаёт, платежи не принимает, чаты не создаёт и не модерирует. Существующий чат можно привязать командой администратора.

## Одна команда для локального запуска

Требуются Docker Engine / Docker Desktop с Linux containers и Docker Compose v2 с поддержкой `--wait`, минимум 4 ГБ доступной памяти, 10 ГБ свободного места для образов. Интернет нужен для первой установки зависимостей и загрузки изображений. Базовый каталог есть в архиве.

Windows, из распакованной папки проекта:

```powershell
.\start-demo.bat
```

Linux/macOS, Python 3 уже установлен:

```sh
sh start-demo.sh
```

Скрипт создаёт `.env`, если его нет, генерирует секреты, собирает Docker и поднимает все локальные компоненты. Адрес: http://localhost:8080. В верхней панели можно переключаться между локальными пользователями «Павел» и «Аня», пароли не нужны. Это только локальные учётные записи. В production этот способ входа отключён.

Эквивалентная команда после создания `.env` через `python3 scripts/init_env.py`:

```sh
docker compose -f compose.yaml -f compose.demo.yaml up --build -d --force-recreate --wait --wait-timeout 900
```

Время ожидания готовности БД не является временем сборки. Требование конкурса: сборка до 300 секунд без первоначальной загрузки базовых образов. Для честного замера без кеша приложения выполните `python3 scripts/measure-build.py` (Windows: `py scripts/measure-build.py`). Скрипт сначала скачивает базовые образы, затем измеряет `docker compose build --no-cache`. Результат сохраняется в `build-report.local.json`. В среде подготовки Docker недоступен, норматив 300 секунд ещё не подтверждён.

## Состав и архитектура

| Компонент | Назначение | Внутренний порт |
|---|---|---|
| frontend | React + TypeScript, статическая сборка через Nginx, прокси API | 80 |
| api | FastAPI, вход MAX, профиль, поиск, подборки и голоса | 8000 |
| db | PostgreSQL 16, постоянный том `postgres_data` | 5432 |
| worker | Очередь личных уведомлений MAX из PostgreSQL | нет |
| catalog | Последовательное обновление разрешённых источников | нет |
| https | Caddy, только при размещении, HTTPS и прокси к frontend | 80/443 |

Браузер обращается к `/api/` на том же домене. Nginx пересылает запросы в API. API читает и изменяет PostgreSQL. Отдельный worker отправляет сообщения бота. Отдельный catalog обновляет данные. Redis, Kubernetes, отдельный сервер моделей и мобильные бинарные приложения не требуются.

Публично доступны только 80/443. Локальный порт 8080 по умолчанию привязан к 127.0.0.1. Порты БД и API на хост не публикуются. При демонстрации с телефона по локальной сети можно временно задать `APP_BIND_IP=0.0.0.0`, но demo не следует открывать в интернете.

## Зависимости и воспроизводимость

Python 3.12: `backend/requirements.lock` фиксирует прямые и транзитивные версии. `backend/requirements.txt` описывает верхний уровень зависимостей. Node.js 22: `frontend/package-lock.json`, установка через `npm ci`. В Docker нет установки тестовых библиотек и локальной языковой модели. Контейнер API запускается непривилегированным пользователем.

Основные библиотеки распространяются по открытым лицензиям. Их версии, лицензии и доступные тексты лицензий перечислены в `THIRD_PARTY_NOTICES.txt`. Оригинальные лицензии зависимостей продолжают действовать. MAX Bridge загружается с официального адреса платформы и является частью обязательной интеграции MAX.

## Переменные окружения

Файл `.env` создаётся автоматически и не должен попадать в репозиторий или публичный архив. `.env.example` содержит только примеры без рабочих доступов.

| Переменная | Назначение |
|---|---|
| APP_ENV | `development` локально, `production` на сервере |
| DEMO_MODE | `true` только локально, `false` на сервере |
| POSTGRES_DB / POSTGRES_USER | Имя базы и пользователь, по умолчанию `app` |
| POSTGRES_PASSWORD / DATABASE_URL | Согласованные пароль и строка подключения, создаются скриптом |
| SESSION_SECRET | Секрет подписи сессий, минимум 32 символа, генерируется |
| MAX_BOT_TOKEN | Токен выданного команде бота, только сервер |
| MAX_BOT_NAME | Имя пользователя бота без `@` |
| MAX_WEBHOOK_SECRET | Секрет webhook, минимум 32 символа, генерируется |
| APP_DOMAIN | Домен без протокола, нужен Caddy |
| PUBLIC_APP_URL | Полный HTTPS-адрес приложения |
| APP_BIND_IP / APP_PORT | Привязка локального frontend, по умолчанию 127.0.0.1:8080 |
| CATALOG_REFRESH_ENABLED | Обновление источников, по умолчанию true |
| CATALOG_REFRESH_SECONDS | Период обновления, по умолчанию 21600 секунд (6 часов) |
| CATALOG_LIVE_SOURCES | Разрешённые загрузчики через запятую, по умолчанию только `KudaGo` |
| KUDAGO_API_URL | https://kudago.com/public-api/v1.4 |
| TIMEPAD_API_TOKEN | Необязательный доступ Timepad, без ключа Timepad не подключён |
| LLM_ENABLED | По умолчанию false, работает встроенный разбор запросов |
| LLM_BASE_URL / LLM_MODEL | Опциональная Ollama и Qwen, не нужны для конкурсного запуска |
| LLM_TIMEOUT_SECONDS | Тайм-аут необязательной модели, 25 секунд |
| APP_BINDINGS_FACTORY | Внутренняя конфигурация, оставьте `app.bindings:build` |

Не заменяйте пароль БД в `.env` после создания тома без отдельной смены пароля в PostgreSQL. Скрипт настройки production сохраняет существующие секреты базы.

## Данные и интеграции

При первом старте `init` применяет миграции и импортирует подготовленные снимки из `seed`. Это нормализованные записи реальных источников, собранные ранее, а не подтверждение текущей доступности каждого сайта. В них есть ссылки и время получения. Датированные завершённые события скрываются. Места без точной даты считаются свежими 30 дней после проверки. Расписания ограничены опубликованным горизонтом до шести месяцев.

В версии 1.3.2 по умолчанию сетевое обновление включает только документированный открытый API KudaGo. Условия: https://docs.kudago.com/api/. Карточки и детали содержат прямые ссылки на материал, без nofollow/noindex. Неизвестная цена не считается бесплатной. Сведения об источниках и последней попытке доступны через `/api/v1/sources?city=krd`.

Прямой загрузчик недокументированного API KASSIR удалён. Его подготовленные записи сохранены как часть исходного снимка, без заявлений о действующей интеграции или партнёрстве. Остальные загрузчики сайтов отключены по умолчанию. Возобновлять их можно только после проверки условий источника и, где требуется, разрешения. Политика данных и ограничения прав изложены в `DATA_SOURCES.md`. Если организатор запрещает конкретный подготовленный набор, его необходимо исключить до фиксации версии. Статус юридического согласования сторонних снимков не подтверждён.

Недоступность источника не обнуляет последний каталог. Обновление на реальном сервере следует подтвердить по журналу `catalog`. Подготовленные данные нельзя представлять как живые интеграции.

Поиск по умолчанию работает без платной LLM. Он распознаёт поддерживаемые категории, город, число людей, бюджет и распространённые опечатки. Произвольное понимание любого текста не гарантируется. При отсутствии точного результата альтернативы идут отдельно с пояснением изменённых условий. Цена `до N` ограничивает начальную цену билета, а `price_match=strict` — верхнюю границу известного диапазона. Общий бюджет делится на число участников. Фильтр бесплатного требует обе цены 0.

## Размещение в MAX

Полная пошаговая инструкция: `DEPLOY_RU.md`. В MAX указывается URL работающего сервиса. ZIP в MAX не загружается.

На новом Ubuntu-сервере, в папке проекта:

```sh
sudo bash scripts/install-docker-ubuntu.sh
python3 scripts/configure-production.py
sudo docker compose -f compose.yaml -f compose.production.yaml up --build -d --force-recreate --wait --wait-timeout 900
```

Скрипт запросит домен, имя и токен бота. Токен вводится скрыто. Домен должен указывать на IP сервера. Открытые порты: 22 для SSH, 80 и 443 для Caddy.

После получения сертификата укажите URL в настройках бота MAX и подключите webhook:

```sh
sudo docker compose exec api python bot_manage.py inspect
sudo docker compose exec api python bot_manage.py subscribe
sudo docker compose exec api python bot_manage.py subscriptions
```

MAX API и открытый API KudaGo — внешние сервисы, не воспроизводимые в контейнерах. Для реального MAX необходимы действующий выданный токен, доступ к настройкам бота, публичный HTTPS и два аккаунта MAX для проверки совместного сценария. Без этого контейнеризация не заменяет работающее решение в MAX.

## Сценарий проверки и ожидаемое поведение

1. В локальном режиме выберите Павла. В MAX используйте собственный аккаунт. Сохраните Краснодар, возрастную группу и интерес «Музыка».
2. Введите «нас 5 человек мы хотим сходить на концерт в Краснодаре». В выдаче ожидаются концерты Краснодара. Число участников не требует, чтобы карточка продавала сразу пять билетов.
3. Введите «стенап до 3000». Опечатка исправляется, выводятся подходящие стендапы, если они есть в каталоге города. Отсутствие категории даёт отдельные альтернативы, а не выдачу их за точное совпадение.
4. В фильтрах укажите бесплатно. Все точные результаты имеют нулевую цену. Для бюджета до 1000 начальная цена результата не превышает 1000.
5. Добавьте 2–5 разных событий и создайте подборку. Откройте её вторым участником. Числа голосов до первого собственного выбора скрыты.
6. Проголосуйте за два варианта. Оба остаются выбранными. Нажмите выбранный вариант повторно: голос отменится. После отмены всех голосов результаты снова скрыты.
7. Откройте подробности. Видны афиша, сеансы, источник и время получения данных. Кнопка «Найти чат события» показывает модальное окно при отсутствии зарегистрированного чата.
8. Включите отслеживание будущего сеанса. В demo задание видно в журнале, реальных сообщений нет. В MAX после начала диалога с ботом должно прийти личное подтверждение. Время напоминания и повторная отправка проверяются отдельно на сервере.
9. Повторите пункты 1–8 в мобильном MAX и web.max.ru. Адаптивный браузерный просмотр сам по себе не подтверждает проверку внутри MAX.

## API и материалы технической проверки

- `/health` — API и соединение с базой.
- `/api/v1/runtime` — версия и режим.
- `/api/docs` — интерактивное описание методов.
- `/api/openapi.json` — OpenAPI 3.1.0, идентично поставляемому `openapi.json`, кроме адреса сервера.
- `DATA-API.yaml` — обязательные проверки, роли, параметры, статусы и ожидаемые поля.
- `review-data.json` — воспроизводимые примеры запросов и правила выбора ID из живого каталога.

Защищённые методы используют `Authorization: Bearer ...`. Токен сессии получается обменом подписанного MAX initData на `/api/v1/auth/max` и действует один час. Паролей собственного сервиса нет. Для проверки жюри открывает приложение своими аккаунтами MAX. Токен бота не является Bearer-токеном пользователя. В локальном режиме `POST /api/v1/auth/demo` с `{"user":"pavel"}` или `{"user":"anya"}` выдаёт локальную сессию. В production этот метод возвращает 404.

Перед сдачей выполните `python3 scripts/prepare-submission.py` и введите публичный адрес, имя бота, ссылку на код и состав команды. Скрипт обновит адрес в OpenAPI и DATA-API. Неизвестный официальный машинный формат DATA-API в PDF не задан: текущая схема покрывает перечисленные поля; если организаторы предоставят шаблон, перенесите данные в него.

## Остановка, повторный запуск и обновление

```sh
docker compose stop
docker compose -f compose.yaml -f compose.demo.yaml up -d
```

Для production во всех командах управления используйте `-f compose.yaml -f compose.production.yaml`, чтобы включить Caddy. Обновление файлов и пересборка сохраняют том базы. После дедлайна исходники и презентацию не изменяют до разрешённого этапа финалистов.

Не используйте `down -v`, если хотите сохранить базу. Для резервной копии:

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

Диагностика:

```sh
docker compose -f compose.yaml -f compose.production.yaml ps
docker compose -f compose.yaml -f compose.production.yaml logs --tail=100 api https catalog
```

## Известные ограничения и границы проверки

Локально проверены 30 сценариев API, договорённости OpenAPI, сборка интерфейса, несколько голосов и отмена, модальное окно чата и мобильная ширина 390 px. База локальной проверки SQLite, рабочая база PostgreSQL. Docker/PostgreSQL, холодная сборка до 300 секунд, реальный MAX и доставка его сообщений пока требуют проверки после размещения. Это не подтверждение допуска жюри.

В каталоге нет гарантии полноты, наличия мест и цены конкретного билета. Часть городов пуста. В исходном срезе Краснодара мало бесплатных вариантов. Процент совпадения показывает соответствие выбранным интересам, а не вероятность понравиться. Спрос, экономия времени, конверсия и финансовые гипотезы ещё не измерены в пользовательском пилоте.
