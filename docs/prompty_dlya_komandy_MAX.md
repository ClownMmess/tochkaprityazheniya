ЧТО МЫ ДЕЛАЕМ

Это мини-приложение и один бот внутри MAX. Пользователь:

1. выбирает возрастную группу, интересы, жанры и любимых исполнителей;
2. просматривает реальные мероприятия Москвы и Краснодара;
3. использует фильтры или пишет запрос обычными словами;
4. получает реальные события из нашей базы и объяснение рекомендаций;
5. при пустом результате получает рабочие варианты ослабления ограничений;
6. отслеживает событие и получает напоминание от бота;
7. создаёт совместный выбор из трёх событий и отправляет ссылку друзьям;
8. после голосования видит победителя;
9. может добровольно вступить в заранее созданный чат события;
10. в чате работает гибридная модерация: правила для явного спама, локальная LLM для неоднозначного текста.

ЗАФИКСИРОВАННАЯ АРХИТЕКТУРА

- frontend: React + TypeScript + Vite;
- backend: Python + FastAPI;
- PostgreSQL, SQLAlchemy, Alembic;
- REST + OpenAPI;
- один бот MAX для мини-приложения, личных напоминаний и групповой модерации;
- KudaGo API v1.4 как единственный внешний источник P0;
- локальный Ollama, стартовая модель qwen2.5:3b;
- Docker Compose;
- процессы: frontend, api, worker, db;
- очередь фоновых заданий через таблицу jobs в PostgreSQL, без Redis и Celery;
- бесплатная публикация с ноутбука через Cloudflare Quick Tunnel;
- seed-набор реальных событий на случай недоступности KudaGo.

Не добавляй микросервисы, Redis, Kafka, Kubernetes, RabbitMQ или платные API. Не предлагай второй источник событий до готовности P0.

МОЯ ЗОНА ОТВЕТСТВЕННОСТИ

Я технический лидер и владею:

- всем каталогом frontend/;
- frontend/src/shared/max/ — MAX Bridge, initData, deep links и sharing;
- backend/app/integrations/llm/ — адаптер Ollama, JSON Schema и fallback;
- backend/app/integrations/max/ — MAX Bot API client;
- backend/app/bot/ — webhook, диспетчеризация и модерация;
- backend/app/worker/runner.py — выполнение фоновых jobs;
- backend/app/main.py — итоговая интеграция роутеров;
- compose.yaml, Dockerfile, .env.example;

Если для моей части нужно изменение, сначала сформулируй точное предложение: файл, поле, причина и обратная совместимость.

ВАЖНЫЕ ПРАВИЛА

- Используй только официальную документацию MAX на dev.max.ru. Не придумывай методы API.
- Не проси меня вставлять token в код или чат. Все секреты только в .env, в репозитории находится .env.example.
- Для авторизации frontend передаёт исходный window.WebApp.initData, backend проверяет HMAC. initDataUnsafe не является доверенной авторизацией.
- LLM только превращает текст в SearchIntent и классифицирует спорные сообщения. Она не создаёт события, цены, адреса и ссылки.
- Ответ LLM должен соответствовать JSON Schema, проверяться Pydantic и иметь timeout 5 секунд, одну повторную попытку и fallback.
- Webhook должен быстро проверить secret, сохранить job и вернуть 200. LLM и удаление сообщений выполняет worker.
- В MAX используется один бот. Личные сообщения и групповые события разделяются по типу чата и наличию chat_id в таблице event_chats.
- Не хранить полный текст сообщений после завершения модерации.
- Каждый рабочий шаг должен завершаться конкретной проверкой или тестом.
