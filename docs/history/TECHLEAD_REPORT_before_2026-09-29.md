Реализованы пользовательские сценарии P0 и функции P1: быстрые сценарии, совпадения профилей группы, жалобы, поддержка нескольких зарегистрированных чатов и фактический счётчик каталога при загрузке. ## Что проверял браузер

Реальный каталог → профиль → отдельные тестовые сеансы → запрос и пустой результат → рабочее ослабление → выбор трёх событий → голос первого пользователя → копирование ссылки → профиль и голос второго → обновление → отслеживание → жалоба → ICS → обработанное уведомление → отмена → перезагрузка. Также проверялось отсутствие необработанных JavaScript-ошибок.

В браузерном тесте используется demo-вход, отключён сетевой MAX Bridge и выключена Ollama. Это проверка приложения и его DB-интеграции, а не доказательство работы внешней платформы.

## Обязательная проверка на компьютере команды

- Docker Compose с **PostgreSQL 16**, включая повторный запуск с сохранённым volume. Docker daemon в среде подготовки отсутствует; сборка Docker и Windows BAT здесь не выполнялись.
- Настоящий MAX initData с двух аккаунтов, Mini App Bridge/shareMaxContent, доставка личного сообщения, реальные webhook retries и права администратора группы.
- Работа qwen2.5:3b на вашем оборудовании. Подготовлены 20 контрольных запросов, JSON Schema, timeout/retry/fallback; качество и скорость живой модели здесь не измерялись.
- Quick Tunnel и настройки mini-app. Публичный стенд не развёрнут без вашего токена и компьютера.
- Мобильный и веб-клиенты MAX. Выполнен мобильный viewport Chromium, а не запуск нативного клиента MAX.

PGlite выполняет PostgreSQL SQL и миграцию, но использует один встроенный движок с мультиплексированием. Он не заменяет нагрузочную проверку многопроцессного PostgreSQL и конкурирующих worker. Транзакционные блокировки реализованы в коде; промышленная exactly-once доставка внешним API не обещается.

## Данные и эксплуатация

Реальный seed не синтетический. Его возраст будет увеличиваться: перед показом запустите import-events. Изображения берутся с адресов источника; при недоступной картинке интерфейс показывает нейтральную обложку. HTTP 200 страницы не подтверждает наличие билетов.

Для продолжительного использования понадобятся постоянный HTTPS, мониторинг/резервные копии, периодический запуск импорта и отдельный эксплуатационный прогон. Эти работы не маскируются под выполненный P2.
