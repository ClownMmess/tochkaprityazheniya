# Проверка P0 и демонстрация

Это подготовленный сценарий, не запись выполненного прогона. Требуются реальная PostgreSQL с seed Ани, включённый Ollama, командный бот и два аккаунта MAX.

## Приёмка перед feature freeze

| Сценарий | Ожидаемый результат | Отметка после живого теста |

## Показ на 2–3 минуты

0:00–0:20 — проблема: компании сложно найти подходящее событие и договориться. Открыть мини-приложение из командного бота, показать ранее сохранённые интересы.

0:20–0:55 — ввести один заранее проверенный запрос. Показать настоящие карточки, фактическую причину и источник. Коротко показать запрос без результатов и рабочую кнопку ослабления.

0:55–1:35 — выбрать три события, создать подборку, нажать «Поделиться в MAX». Второй аккаунт открывает ссылку и голосует. Обновить голоса и показать лидера.

1:35–2:10 — открыть событие, включить tracking, показать пришедшее подтверждение от того же бота. Перейти по приглашению в чат добровольно.

2:10–2:40 — на заранее согласованном тестовом сообщении показать модерацию. Не использовать реальные чужие сообщения для демонстрации удаления. Завершить архитектурой: один бот, реальные данные, локальная модель, проверяемые рекомендации.

Для живого reminder выбрать реальный ближайший сеанс и допустимое remind_before_minutes. Не переносить реальные даты мероприятий ради демонстрации. Если времени нет, отдельно показать confirmation и запись успешно проверенного reminder.
