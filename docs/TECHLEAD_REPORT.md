# Проверка выпуска 1.2.0 — 29 сентября 2026

Исправления по 13 замечаниям: RELEASE_1_2.md. Цвета и основное оформление сохранены. Нормализованные сущности Ани, авторизация MAX, личное отслеживание, голоса, очередь и модерация сохранены.

## Проверки

- Backend: 93 теста прошли полным запуском `pytest -q`; затем отдельно прошла новая проверка сохранения места без выдуманной даты, без напоминания о 1970 годе и без календарного события. Итого 94 проверяемых случая.
- Frontend: 4 теста Vitest и production-сборка TypeScript/Vite.
- PostgreSQL: 23 интеграционных теста прошли через PGlite 0.5.8 / socket / psycopg. После последнего расширения миграции выполнен отдельный чистый полный импорт всех снимков: 645 записей KudaGo, 155 записей площадок, 7495 расширенного снимка. `GET /health` вернул status=ok/database=ok; каталог концертов ответил. Это PostgreSQL-совместимый движок, не Docker postgres:16 на Windows.
- Chromium / Playwright с настоящим API и БД, без подмены ответов каталога: музейный запрос; рэп; опечатка; вопрос и сохранение контекста; автоматическое добавление следующей порции ленты; возврат в загруженную подборку; 18 быстрых кнопок и соответствие строки запросу; равенство возраста; загрузка реальной картинки в подробностях; доступный выбранный сеанс; пять вариантов голосования. Ширины 360/390/1440 px, горизонтального переполнения и JS-ошибок не обнаружено.
- Источники получены по сети, пагинация KASSIR.RU до конца. Снимки сохранены в seed. Сопоставлены категории, группы дат и жанры; проверен контрольный локальный час KASSIR с BASE.
- Планировщик проверен на повторный запуск; реальные адаптеры чтения источников использовались при подготовке снимков. Шестичасовой настенный интервал в этой сессии не ожидался.

## Воспроизведение

```bash
cd backend
python -m pytest -q
cd ../frontend
npm test
npm run build
E2E_BASE_URL=http://localhost:8080 node scripts/release12-e2e.cjs
```

Браузерный тест создаёт тестовые профили, голосование и голоса в локальном режиме. Запускайте его на тестовой базе. Публичные фото грузятся с источников; при их недоступности UI использует текстовую обложку.

## Границы проверки

В среде подготовки нет Docker daemon и PowerShell. Docker Desktop/Windows и аппаратная производительность Qwen 7B не проверялись. Скрипты запуска настроены по официальной документации Docker/Ollama, сохраняют работающий .env и проверяют health, версию фронтенда и ответ LLM. Живой MAX требует токена, HTTPS и прав бота; использовался локальный режим доставки.

Не заявляется увеличение качества «на 50%» или охват абсолютно всех событий города. Неподтверждённые даты и цены не генерируются. Для мест нет синтетических сеансов, для периодов прямо указано отсутствие точного расписания. Восемь источников имеют данные; Timepad не считается подключённым без доступа.

## Протокол и обновление

Миграция 12_catalog_places добавляет fields kind/schedule_note/import_version у события и schedule_kind/external_url у сеанса. Старые таблицы и ключи сохраняются. Новые KASSIR-сеансы группируются в одну карточку по названию и площадке; цена и билетная ссылка остаются на сеансе. Базовый дизайн не заменялся.

Импорт выполняется отдельным сервисом catalog после старта и каждые 21600 секунд. Неудача одного источника не стирает базу. PostgreSQL advisory-lock предотвращает пересечение с ручным импортом. Старые снимки не откатывают более свежие события. Счётчики и ошибки доступны через GET /sources.
